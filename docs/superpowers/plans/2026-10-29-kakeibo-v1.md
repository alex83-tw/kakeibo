# kakeibo v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建出 kakeibo：手機優先、單人使用的家計簿（今日、帳本、對帳、設定，加電腦版見開き），共用既有 Supabase 資料庫。

**Architecture:** Next.js App Router。純函式的領域層（`lib/`，時間、金額、分類、餘額、預算、對帳、示警）用 TDD 先做；資料層用薄的 repository 加 server actions；UI 用 Server Components 讀資料、Client Components 只放互動（長條滑桿、記一筆輸入單）。資料表異動以 idempotent SQL 檔交給使用者執行。

**Tech Stack:** Next.js 16、TypeScript strict、Tailwind CSS 4、Radix UI（Dialog）、Supabase（`@supabase/supabase-js`、`@supabase/ssr`）、Vitest + Testing Library。本計畫**不引入** React Query 與 Recharts（Server Components、server actions 與 CSS 長條已足夠，之後需要再加）。

**Spec:** `docs/superpowers/specs/2026-10-29-kakeibo-design.md`；視覺與互動參考 `docs/superpowers/specs/assets/hani-sketch-v9.html`。

## Global Constraints

- UI 全繁體中文（台灣）。
- 所有日期與月界用 `Asia/Taipei`；禁止用 UTC `toISOString()` 取月界。
- 第一版只支援 TWD；非 TWD 的列排除於餘額、預算、一致性之外，帳本以「未納入」標示。
- 色：墨 `#1A1D1B`、朱 `#C13A2B`、青緑 `#2B7A68`、紙 `#F7F7F3`。朱只給「需要處理」（注意、差、預估超支），青緑只給「對上」；任何顏色意義都要附文字。
- 字：最小 13px；字級 figure 2rem、title 1.25rem、body .9375rem、label .8125rem；金額 `tabular-nums`；`NT$` 與金額不可斷行；數字用 Noto Serif 子集，內文 Noto Serif TC 400／700。
- 內容區行線每 36px；點擊目標 ≥ 44×44px；每條注意 48px 高。
- 差＝帳面−帳單，△ 表示帳面較少；白話「帳面比帳單多欠 320」。
- 分類兩層文字（主＋子）；預算只在主分類；子分類預設「一般」，儲存為 `other`。
- 轉帳是單一列（`entry_type='transfer'`，帶 `account_id` 與 `transfer_account_id`），不計入收入與支出。
- 每個查詢都帶 `user_id`；軟刪除在 SQL 過濾（`deleted_at is null`），不在 JS 事後過濾。
- 不蓋章；不顯示頁碼。
- Migrations：idempotent SQL 放 `migrations/`，由使用者自己執行；大量 UPDATE 包 `BEGIN;` … `ROLLBACK;` 並附斷言；每個任務結束列出尚未執行的 migration。查詢新欄位前先確認 migration 已跑。
- 不讀取或使用儲存的憑證；需憑證的步驟請使用者手動執行。
- 瀏覽器專用 API（`localStorage`、`window`）要防 SSR。
- 提交前跑 `npm run typecheck`、`npm run lint`、`npm test`，回報實際通過數。改 UI 後用 Playwright 真實操作再截圖；Playwright 瀏覽器是共用資源，遇到「已被使用」不要重試迴圈，回報後等使用者指示。
- 推送前確認 git 帳號；本計畫不 push。
- 不做：投資／資產／退休／負債／保險、現金流預測、離線佇列、推播與 Email、調整分錄。
